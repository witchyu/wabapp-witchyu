# Witchyu — Mobile Booking App

เว็บแอปจองคิวดูดวง (Mobile-first) — **ตอนนี้อยู่ PHASE 4: Admin Dashboard**

```
witchyu/
├── frontend/   React + TypeScript + Vite + Tailwind
└── backend/    Node.js + Express + TypeScript + Prisma + PostgreSQL (Neon)
```

## อัปเดตจาก Phase 3 เป็น Phase 4 (วางไฟล์ทับของเดิม)
> ทำใน Codespaces Terminal · ไม่ต้องลบอะไรเอง สคริปต์จัดการให้และสำรองของเดิมไว้ให้

1. หยุดเซิร์ฟเวอร์ที่รันอยู่ (Ctrl+C ทุก Terminal)
2. (แนะนำ) บันทึกสถานะปัจจุบันไว้ก่อน: `git add -A && git commit -m "before phase 4"`
3. อัปโหลด `witchyu-phase4.zip` เข้า Codespaces (Explorer → กดค้างที่พื้นที่ว่าง/คลิกขวา → **Upload...**)
4. แตก zip ไปที่ **โฟลเดอร์ชั่วคราว** (ห้ามแตกลงในโปรเจกต์โดยตรง):
   ```bash
   unzip -o witchyu-phase4.zip -d /tmp/p4
   ```
5. `cd` ไปที่โฟลเดอร์โปรเจกต์ของคุณ (โฟลเดอร์ที่ `ls` แล้วเห็น `frontend` กับ `backend`) แล้วรัน:
   ```bash
   bash /tmp/p4/witchyu/apply-phase4.sh
   ```
6. ทำตามขั้นตอนที่สคริปต์พิมพ์ออกมา (สรุป): ใส่ `ADMIN_USERNAME`/`ADMIN_PASSWORD` ใน `backend/.env` → `npm install` → `npm run db:push` → `npm run db:seed` → `npm run admin:create` → **ลบบรรทัด `ADMIN_PASSWORD`** → `npm test` → `npm run dev`
7. อีก Terminal: `cd frontend && npm install && npm run build && npm run dev` แล้วเปิดแอปต่อท้ายด้วย `/admin`

สคริปต์จะ: สำรองไฟล์เดิมไว้ที่ `.backup-before-phase4-<เวลา>` · ลบโค้ดเก่าที่ถูกแทนที่แล้วคัดลอกของใหม่ (ไม่ให้ไฟล์เก่าที่เลิกใช้ตกค้างจนทำให้ build พัง) · **ไม่แตะ** `node_modules`, `backend/.env`, `.git` · สร้าง `ADMIN_TOKEN_SECRET` ให้ใน `.env` · รันซ้ำได้ปลอดภัย
ถ้าแก้ไฟล์หน้าเว็บไว้เอง ให้ดูในโฟลเดอร์สำรอง แล้วคัดลอกส่วนที่ต้องการกลับมาได้
ถ้าต้องการย้อนกลับทั้งหมด: `git checkout . && git clean -fd` (ใช้ได้เมื่อทำข้อ 2 ไว้)

## Admin (Phase 4)
เปิดที่ `/admin` (แยกจากแอปลูกค้า) ล็อกอินด้วยบัญชีที่สร้างจาก `npm run admin:create`
- **ภาพรวม**: จำนวนคิววันนี้/รอชำระ/ยืนยันแล้ว, สวิตช์ **เปิด-ปิดรับจองคิว** และ **เปิด-ปิดรับจองโทร**, คิวที่จะถึง
- **การจอง**: ตาราง วันที่/เวลา · บริการ · ราคา · ลูกค้า · อายุ · สถานะ · หมายเหตุ · Actions (ดูรายละเอียด / ยืนยัน / ยกเลิก / แชต / โทร) พร้อมค้นหา กรองสถานะ-วันที่ และแบ่งหน้า
- **บริการ**: เพิ่ม แก้ไข (ชื่อ ราคา คำถามในเซ็ต ฯลฯ) ลบ เปิด/ปิด
- **รอบเวลา**: เพิ่ม ลบ เปิด/ปิด และกำหนดจำนวนคิวสูงสุดต่อรอบ
- **เวลาทำการ**: เวลาเปิด-ปิดรายวัน และปิดทำการทั้งวันได้
- **วันหยุด / ปิดรับจองรายวัน**: เลือกวันที่ที่จะปิดรับจองทุกรอบ

ทุกอย่างบันทึกลง Database จริง และมีผลกับลูกค้าทันที (แอปลูกค้าอ่านสถานะล่าสุดจากเซิร์ฟเวอร์ทุกครั้งที่เปิด/กลับมาที่แท็บ)

### ความปลอดภัยของ Admin
- รหัสผ่านเก็บเป็นค่าเข้ารหัส (scrypt) เท่านั้น ไม่เก็บตัวจริง และไม่ต้องเขียนไว้ในโค้ด
- ล็อกอินได้ด้วยโทเคนมีอายุ 8 ชั่วโมง เซ็นด้วย `ADMIN_TOKEN_SECRET` (อย่าเปิดเผย/อย่าขึ้น GitHub)
- ล็อกอินผิด 5 ครั้งต่อชื่อผู้ใช้ (หรือ 15 ครั้งต่อ IP) ภายใน 15 นาที จะถูกชะลอ
- ทุกเส้นทาง `/api/admin/*` ที่ไม่ใช่ล็อกอิน ต้องแนบโทเคนที่ถูกต้อง
- ระบบความปลอดภัยทั้งชุด (ล็อกอินลูกค้า, Session, Rate limit ทั่วระบบ ฯลฯ) ยังเป็นงาน Phase 8
- ถ้าลืมรหัสผ่าน: ใส่ `ADMIN_USERNAME`/`ADMIN_PASSWORD` ใหม่ใน `.env` แล้วรัน `npm run admin:create` อีกครั้ง

## ปรับแต่งหน้าตาเว็บได้เองเสมอ (แม้ทำครบทุก Phase แล้ว)
หน้าตาทั้งหมดอยู่ใน `frontend/src` และไม่ผูกกับ backend/Database
| อยากเปลี่ยน | แก้ที่ |
|---|---|
| สี (ทอง/พื้นหลัง/ตัวอักษร) | `frontend/tailwind.config.js` (ส่วน `colors`) |
| ฟอนต์ | `frontend/index.html` (ลิงก์ Google Fonts) + `tailwind.config.js` (`fontFamily`) |
| โลโก้/ไอคอน | แทนที่ `frontend/public/icon.png` |
| ข้อความ/เลย์เอาท์แต่ละหน้า | `frontend/src/pages/*.tsx` และ `frontend/src/components/*` |
| เมนูล่าง | `frontend/src/components/BottomNav.tsx` |
| ราคา ชื่อบริการ คำถามในเซ็ต รอบเวลา เวลาทำการ วันหยุด | **ไม่ต้องแก้โค้ด** ทำที่หน้า `/admin` |

ข้อแนะนำ: `git commit` ก่อนแก้ทุกครั้ง · แก้เสร็จรัน `npm run build` (ใน `frontend/`) เพื่อเช็กว่าไม่พัง · อย่าเปลี่ยนชื่อฟิลด์ที่คุยกับ API (เช่น `serviceIds`, `status`) ถ้าไม่ได้แก้ backend ด้วย

## ฐานข้อมูล: Neon (Postgres ฟรี)
เลือก Neon เพราะแพ็กเกจฟรีไม่มีวันหมดอายุและไม่ต้องใช้บัตร (ตรวจเงื่อนไขล่าสุดเมื่อ ต.ค. 2026: 0.5 GB ต่อโปรเจกต์, 100 CU-hours ต่อเดือน, พักเครื่องอัตโนมัติเมื่อไม่มีคนใช้)
**ไม่ใช้ Postgres ฟรีของ Render** เพราะหมดอายุใน 30 วันแล้วข้อมูลถูกลบ

ข้อมูลของแอปนี้เป็นข้อความเล็ก ๆ 0.5 GB เก็บการจองได้หลายแสนรายการ ส่วนโควตาคอมพิวต์ ผมออกแบบให้ประหยัด: ไม่มี timer ยิงฐานข้อมูล และ `/api/health` ไม่แตะฐานข้อมูล เพื่อให้ Neon พักเครื่องได้เมื่อไม่มีคนใช้ (ถ้าเครื่องตื่นค้างตลอดเดือน โควตาจะหมดก่อนสิ้นเดือน)

## เริ่มใช้งานครั้งแรก
1. สมัคร https://neon.com → New Project (Region: **Singapore**)
2. กด **Connect** → **ปิด** สวิตช์ "Connection pooling" → คัดลอก connection string
3. ในโฟลเดอร์ `backend/`
   ```bash
   cp .env.example .env     # แล้วเปิดไฟล์ .env วาง connection string ที่ DATABASE_URL (ต่อท้าย &connect_timeout=15)
   npm install
   npm run db:push          # สร้างตารางทั้งหมด
   npm run db:seed          # ใส่บริการ 38 รายการ + รอบเวลา + เวลาทำการ
   npm test                 # ทดสอบตรรกะ (ไม่ต้องใช้ฐานข้อมูล)
   npm run dev              # API ที่พอร์ต 4000
   ```
4. เปิดอีก Terminal ในโฟลเดอร์ `frontend/`
   ```bash
   npm install
   npm run dev              # เปิดผ่านพอร์ต 5173 (Vite ส่งต่อ /api ไป backend ให้เอง)
   npm run build            # ตรวจ TypeScript + build
   ```
ตรวจการเชื่อมต่อฐานข้อมูล: เปิด `http://localhost:4000/api/health/db` ต้องได้ `{"ok":true,"db":true}`

> ใช้ `db:push` ในช่วงพัฒนา — Phase 9 (Production) จะสร้าง migration ชุดแรกก่อน deploy
> แนะนำให้สร้าง Neon branch แยกสำหรับทดสอบ (ฟรี) จะได้ไม่ปนกับข้อมูลจริง

## API (Phase 3)
ส่วนที่เกี่ยวกับการจองต้องส่ง header `X-Client-Id` (หน้าเว็บสร้างให้เองและเก็บในเบราว์เซอร์; Phase 8 แทนด้วยล็อกอินจริง)

| Method | Path | ทำอะไร |
|---|---|---|
| GET | `/api/services` | รายการบริการที่เปิดอยู่ |
| GET | `/api/time-slots?date=YYYY-MM-DD&serviceIds=a,b` | สถานะ ว่าง/เต็ม/ปิด ของแต่ละรอบ |
| POST | `/api/bookings` | สร้างการจอง (เซิร์ฟเวอร์คำนวณราคาและตรวจรอบเอง) |
| GET | `/api/bookings` | การจองของอุปกรณ์นี้ |
| GET | `/api/bookings/:id` | รายละเอียดการจอง (เฉพาะเจ้าของ) |
| PATCH | `/api/bookings/:id` | แก้หมายเหตุ/ข้อมูลผู้จอง/เลื่อนวัน-เวลา |
| POST | `/api/bookings/:id/cancel` | ยกเลิกการจอง |
| POST | `/api/bookings/:id/mock-pay` | ชำระเงินจำลอง (เฉพาะ `ALLOW_MOCK_PAYMENT=true`) |
| GET | `/api/shop` | สถานะร้าน: เปิดรับจองไหม / เปิดรับโทรไหม / เปิดอยู่ตอนนี้ไหม / ข้อความเวลาทำการ |
| GET | `/api/health`, `/api/health/db` | ตรวจสถานะ |

## กฎที่ทำงานฝั่งเซิร์ฟเวอร์
- รอบเต็มจริงตามจำนวนคิวต่อรอบ (ตั้งใน Database: `TimeSlot.capacity`) รายการที่ยืนยันแล้ว หรือรอชำระที่ยังไม่หมด 15 นาที ถือรอบไว้
- จองพร้อมกันรอบเดียวกัน: ใช้ Transaction ระดับ Serializable + ลองใหม่ ผู้ที่มาทีหลังได้ `SLOT_FULL`
- จองล่วงหน้าได้ 7 วัน (เวลาไทย), วันหยุด/วันปิดทำการ/นอกเวลาเปิด-ปิด → ปิดรับ, "โทรไม่จำกัด" เฉพาะ 22:30
- รอชำระเกิน 15 นาที → ยกเลิกอัตโนมัติ, ยืนยันแล้วและเลยเวลานัด → เสร็จแล้ว (อัปเดตทุกครั้งที่มีการเรียก API)
- เลขที่การจอง `WY-YYYYMMDD-NNN`

## ข้อจำกัดที่ตั้งใจไว้ (ทำใน Phase ถัดไป)
- ยังไม่มีล็อกอิน: ใช้รหัสอุปกรณ์แทน (ล้างข้อมูลเว็บ = มองไม่เห็นการจองเดิมจากเครื่องนั้น) → Phase 8
- ตาราง Message, CallSession มีใน Database แล้วแต่ยังไม่ใช้ → Phase 5-6
- ปุ่ม แชต/โทร ในหน้า Admin เป็น Placeholder (แจ้งใน toast) → Phase 5-6
- ลูกค้าที่จองไว้ในวันที่ Admin เพิ่งตั้งเป็นวันหยุด จะไม่ถูกยกเลิกอัตโนมัติ (ระบบแจ้งจำนวนให้ Admin จัดการเอง)
- QR และปุ่มชำระเงินยังเป็นของจำลอง → Phase 7
- ปุ่ม Placeholder: โทร, แชต, การแจ้งเตือน, ความเป็นส่วนตัว, ติดต่อเรา, ออกจากระบบ
- API แก้ไขการจอง (PATCH) พร้อมใช้งานแล้ว แต่หน้าเว็บยังไม่มีหน้าจอเรียกใช้
- ไม่มีแบบทดสอบ/เกม/Quiz ตามที่กำหนด

โปรเจกต์เว็บเดิม (`public/`, `server.js`) ไม่ได้ถูกแก้ไขหรือลบ
