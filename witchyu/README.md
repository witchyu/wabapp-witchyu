# Witchyu — Mobile Booking App

เว็บแอปจองคิวดูดวง (Mobile-first) — **ตอนนี้อยู่ PHASE 2: Booking Logic (ยังไม่มี Backend/Database)**

## รัน
```bash
cd frontend
npm install
npm run dev      # เปิด http://localhost:5173 (Codespaces: เปิดจากแท็บ PORTS พอร์ต 5173)
npm run build    # ตรวจ TypeScript + build
```

## หน้าที่มีใน Phase 1
| Route | หน้า |
|---|---|
| `/` | Home |
| `/services` | บริการทั้งหมด 8 เซ็ตคำถามตามระบบเดิม (+ ดูรายละเอียดคำถามในเซ็ต) |
| `/booking` | จองคิว 5 ขั้นตอน (ข้อมูล → บริการ → วันเวลา → หมายเหตุ → สรุป) |
| `/payment/:id` | ชำระเงิน **จำลอง** |
| `/success/:id` | จองสำเร็จ |
| `/bookings`, `/bookings/:id` | การจอง / รายละเอียด |
| `/chat` | Placeholder (ทำจริง Phase 5) |
| `/profile` | โปรไฟล์ |

## ขั้น "เลือกบริการ"
- เรียงตามเซ็ตคำถามเดิม: เจาะจง (+พิมพ์จำนวนเอง) → โทร → เป็นเรื่องๆ → 2 ทางเลือก → ความรัก 59 → ความรัก 49 → การงาน → การเรียน
- ปุ่ม "เลือกหลายรายการ" / "ยกเลิก" อยู่มุมขวาบนของหน้า (ขั้นที่ 2)
- เปิดโหมดแล้ว 3 เซ็ตแรกถูกบล็อกพร้อมข้อความ "ไม่สามารถเลือกหลายรายการได้" ส่วนที่เหลือเลือกได้หลายรายการจนกว่าจะกดยกเลิก (ยกเลิก = ล้างที่เลือกทั้งหมด)
- ราคาของ "อื่นๆ" (2 ทางเลือก) ใช้ 49 บาทตามระบบเดิม

## Phase 2 — Booking Logic (เก็บใน LocalStorage ของเบราว์เซอร์)
- **Booking State**: ข้อมูลที่กรอกค้างไว้ถูกเก็บและกู้คืนได้เมื่อรีเฟรช (ตรวจความถูกต้องก่อนใช้ทุกช่อง)
- **เลือกบริการ**: เลือกได้ 1 รายการ หรือโหมดหลายรายการเฉพาะ 2 ทางเลือก/ความรัก/การงาน/การเรียน; "อื่นๆ" มีกล่องให้พิมพ์คำถามเอง (บังคับกรอก)
- **วัน/เวลา**: 7 วัน (วันนี้ + 6 วัน) รอบที่ผ่านไปแล้วปิด, "โทรไม่จำกัด" จองได้เฉพาะ 22:30
- **รอบเต็มจริง**: 1 คิวต่อรอบ (`SLOT_CAPACITY` ใน `src/data/shop.ts`) รายการที่ยืนยันแล้ว หรือรอชำระเงินที่ยังไม่เกิน 15 นาที ถือรอบไว้
- **ตรวจซ้ำก่อนสร้างการจอง** (ข้อมูลผู้จอง, บริการ, รอบเวลา) ถ้ามีคนจองรอบเดียวกันตัดหน้า (เช่น เปิดสองแท็บ) จะแจ้งและพากลับไปเลือกเวลาใหม่
- **เลขที่การจอง** `WY-YYYYMMDD-NNN` ไม่ซ้ำต่อวันที่ของคิว
- **ประวัติ**: รอชำระเกิน 15 นาที → ยกเลิกอัตโนมัติ, ยืนยันแล้วและเลยเวลานัด → เสร็จแล้ว
- ไม่มีข้อมูลตัวอย่างอีกต่อไป เริ่มต้นประวัติการจองว่าง
- ตรรกะหลักอยู่ใน `src/utils/bookingRules.ts`, `slots.ts`, `storage.ts` (ไม่ผูกกับ React)

## ข้อจำกัดที่ตั้งใจไว้
- ข้อมูลอยู่ในเบราว์เซอร์เครื่องเดียว (ล้างข้อมูลเว็บ = ประวัติหาย) — Phase 3 ย้ายไป Database
- การจองจากเครื่อง/เบราว์เซอร์อื่นยังไม่เห็นกัน จึงยังกันจองซ้ำข้ามเครื่องไม่ได้ (ทำใน Phase 3)
- ปุ่ม "ฉันชำระเงินแล้ว" และ QR ยังเป็นการจำลอง ไม่ได้ยืนยันเงินเข้าจริง (Phase 7)
- ปุ่ม Placeholder: โทร, แชต, การแจ้งเตือน, ความเป็นส่วนตัว, ติดต่อเรา, ออกจากระบบ
- เวลาในแต่ละรอบ/เวลาเปิด-ปิดร้าน ตั้งในโค้ด (`src/data/shop.ts`) — Admin จัดการใน Phase 4
- ไม่มีแบบทดสอบ/เกม/Quiz ตามที่กำหนด

โปรเจกต์เว็บเดิม (`public/`, `server.js`) ไม่ได้ถูกแก้ไขหรือลบ — โฟลเดอร์ใหม่คือ `frontend/`
